## Git 提交规范（参照 FocusWave，2026-08-10）

- **版本发布提交**：message 以版本号开头，格式 `v{版本} — {主题}：{具体改动}`（中文），并同步打 tag `v{版本}`，与 `docs/版本说明.md` 对应
  - 示例：`v9 — 谐波抑制主线：能量门定位 + 相位方差判别 + iirnotch 陷波（0807 迭代）` → `git tag v9`
- **常规提交**：Conventional Commits 类型前缀 + 简洁描述（英文或中文），聚焦"改了什么 + 为什么"
  - `feat:` 新功能 / `fix:` 修复 / `docs:` 文档 / `refactor:` 重构 / `clean:` 清理 / `chore:` 杂务
  - 示例：`fix: 段参考修正误判倍频（v1.3）`、`docs: 更新版本说明 v9`
- **提交粒度**：一次逻辑改动一个 commit，不混改；换版本思路时先提交再改，不覆盖
- **禁止提交**：`output/` 产物、原始数据（npz/bin）、`__pycache__/`（.gitignore 已管）
- **不修改一敏的代码**：需要时引用，不直接改她的版本

## 目录命名

- 用编号+描述：`01_DebugTool/` `02_SART-30s/`，不用 `data_v1/` `src-v2_bp/` 这种容易混淆的名字
- 算法版本用 `v1/` `v2/` 不用 `bp/` `vmd/`
- 输出按原始数据分组而非算法版本分组，方便跨算法对比

## 文档规范

- `README.md`：目录结构 + 用法 + FAQ + 依赖，不写版本历史
- `版本说明.md`：算法版本演进 + 数据对应表 + 改进方向
- `图表索引.md`：每个图表必须有生成脚本、数据来源、日期
- 图表统一放 `output/figures/`，生成脚本放 `scripts/figures/`
- 文档放 `docs/`，不叫 `参考/`

## 代码规范

- 分析脚本（process）和图表脚本（gen_plots）分开，不混写
- 不修改一敏的代码，缺了找她要
- 一次性脚本用完即删（batch_run_all）
