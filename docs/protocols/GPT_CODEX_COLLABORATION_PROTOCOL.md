# GPT↔Codex 双边协作协议

## 目的

为 GPT 与 Codex 之间提供单一、可追溯、低体积的分析交接方式。GPT 通过 GitHub 读取交接文件，Codex 根据 GPT 写回的裁决继续执行。

## Codex 交接要求

每次交接只提交一份 Markdown 汇总文件，建议路径：

`docs/decisions/YYYY-MM-DD-<topic>-handoff.md`

文件必须包含：

- `RUN_ID`、日期、当前分支和 commit；
- 输入范围与本地数据目录；
- 已执行的入口、配置和 split 规则；
- 关键结果与样本覆盖；
- `formal / exploratory / blocked / unverified` 状态；
- 失败原因、限制和未解决风险；
- 请求 GPT 裁决的问题；
- 本地详细产物索引。

## GitHub 上传边界

允许提交：脚本、配置示例、方法文档、聚合结果、运行清单、审计摘要和裁决文件。

禁止提交：原始数据、被试级 CSV、视频、NPZ、MAT、大型派生文件、个人身份信息、凭据、缓存和运行时数据库。

## GPT 裁决要求

GPT 只依据交接文件及其明确引用的仓库文件进行判断。裁决写入同一仓库的 `docs/decisions/`，并记录 commit hash。裁决必须区分：

- 可以进入正式分析；
- 仅可作为探索性结果；
- 当前阻塞；
- 尚未验证。

GPT 不应在证据不足时改变标签、阈值、数据划分、主要结论或把质量审计升级为效度验证。

## Codex 执行裁决

Codex 拉取裁决 commit 后执行。每次返回必须说明：实际读取的 commit、运行 ID、输入、产物、验证方式、关键结果、剩余风险和下一步。不得把未运行、阻塞或探索性结果写成已完成的正式结果。

## 推荐交接提示词

> 请读取 GitHub 仓库中的交接文件及其明确引用的文件。请先总结各线路状态，再区分正式、探索性、阻塞和未验证结果，最后给出最多三条下一步主线。不要要求上传原始数据；如证据不足，请列出解除阻塞所需的最小文件或信息。
