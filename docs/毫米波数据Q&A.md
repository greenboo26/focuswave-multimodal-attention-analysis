## 基础知识

### Q：BPM 是什么？

**Beats Per Minute（心跳次数/分钟）**。呼吸率也用同样单位但叫 Breaths Per Minute。

换算关系：
- 频率 1 Hz = 60 BPM
- 心率 72 BPM = 1.2 Hz
- 呼吸率 12 BPM = 0.2 Hz

### Q：频域 vs 时域一致性是什么意思？

用两种独立方法算心率，看结果是否一致：

| 方法 | 原理 | 举例 |
|------|------|------|
| **频域** | 对整段波形做频谱分析，找到能量最高的频率 | 1.33Hz 有峰值 → 1.33×60 = **79.9 BPM** |
| **时域** | 逐个找到心跳波峰的位置，计数 | 30秒内 42 个峰 → 42÷30×60 = **84 BPM** |

**如果两者差很大（>15 BPM）**：说明算法有问题，可能是把噪声当成心跳。
**如果接近（<5 BPM）**：算法基本可靠，可以拿来做数据有效性验证。

v2 的 VMD 方法做到差距 3-5 BPM，可以认为时域和频域互相验证通过。

### Q：当前算法的精度够不够验证数据有效性？

**够。** 验证数据有效性只需要确认：

| 检查项 | 方法 | 阈值 |
|--------|------|------|
| 雷达收到信号？ | 距离剖面看峰值 | 近距 bin 有明确目标 |
| 8 通道都工作？ | npz 检查 | 8 个 tx*_rx* key 完整 |
| 帧率稳定？ | CSV 时间戳 | ~97fps，无跳帧 |
| 呼吸可测？ | 呼吸 SNR | > 10:1 |
| 心跳可测？ | 心跳 SNR | > 3:1 |

**这些 30s 数据 + 现有 pipeline 就够。不需要更高级的算法。**

### Q：要不要买金标准设备（ECG/血氧仪）来标定精度？

**写论文或申请专利需要，做原型够用。**

| 场景 | 需要 | 设备 |
|------|------|------|
| 验证数据有效性 | ❌ 不需要 | — |
| 厚粲杯原型演示 | ❌ 不需要 | — |
| 论文报告"心率精度 ±X BPM" | ✅ 需要 ECG 对照 | 单导联 ECG ~500-2000 元 |
| 论文报告 HRV（SDNN/RMSSD） | ✅ **必须** ECG | 毫米波 HRV 本身就是前沿课题 |
| 专利声称算法效果 | ✅ 需要 | 金标准设备记录 |

**HRV 验证最严格**：Wang 2021 mmHRV 用 VMD 做到 IBI 误差 28ms 发了 IEEE IoTJ，这是门槛。

## 算法 Pipeline

### Q：当前算法流程是什么？

v2 pipeline：

```text
load_data()           加载 .npz 或 .datacube.bin → IQ (n_frames, 256, 8)
    ↓
range_fft()           距离FFT (汉宁窗, 256点)
    ↓
select_bins()         按 SNR + 功率阈值选最佳通道和距离门
    ↓
extract_displacement() 相位提取与解卷绕 → 胸壁位移 (mm)
    ↓
[频率估计]             baseline 带通 + periodogram（统一稳定）
    ↓
[信号分离]             bp: 带通滤波 / vmd: VMD (K=4, alpha=1000)
    ↓
detect_peaks()        多阈值搜索 + IBI 评分 + 自相关校正
    ↓
                      HR/BR/HRV计算 → JSON + NPZ + PNG
```

代码在：`08_算法/scripts/process_vital_signs_v2.py`
Baseline 版本：`08_算法/scripts/process_vital_signs_v1.py`（仅有带通滤波）

### Q：v1 → v2 变了什么？

| 改进 | v1 (Baseline) | v2 (当前) |
|------|--------------|-----------|
| 呼吸/心跳分离 | 带通滤波硬切 | VMD 自适应分解 (K=4, α=1000) |
| 峰值检测 | `find_peaks` 固定阈值 | 多阈值搜索 + IBI 评分 + 补漏 |
| select_bins | 纯 SNR 选 bin | SNR + 功率阈值（排除边缘噪声） |
| HR 频域估计 | periodogram | periodogram（统一用 HR bin） |
| 文件 | `process_vital_signs_v1.py` | `process_vital_signs_v2.py` |

### Q：VMD 参数怎么确定的？

通过参数扫描（K=3~6, alpha=1000~5000）在 v2 和 v3 数据上测试，选 K=4, alpha=1000 效果最稳定。

### Q：VMD 调优遇到过什么问题？

三个关键发现：

**① VMD 模态选择不稳定。** 同一数据不同运行可能收敛到不同频率（1.13Hz vs 1.52Hz）。解决方法：频域 HR 用 baseline 带通 + periodogram 估计（稳定可靠），VMD 只做信号净化。

**② VMD 模式下 periodogram 可能错选频点。** VMD 模态频谱的峰值可能落在残余噪声上（0.81Hz 而非 1.13Hz）。解决方法：频域用 VMD 中心频率（CF）或 baseline periodogram，不用 VMD 模态的 periodogram。

**③ VMD 输出峰值检测偏多。** 纯净信号反而让 find_peaks 检出过多峰。解决方法：用已知 HR 频率做窄带带通引导（lo=HR-0.4Hz, hi=HR+0.6Hz）。

### Q：倍频锁定是什么？怎么发现？

**倍频锁定（harmonic locking）**：毫米波测心率的流程是 相位解卷绕 → FFT 频谱 → 找峰值频率 → ×60 = bpm。心跳波形不是纯正弦，频谱里除了真实频率 f0 的峰，还有 2f0、3f0 的谐波峰。正常时 f0 峰最强；但信号变弱、被试移动或呼吸谐波干扰时，f0 峰被压下去，谐波峰反成最高峰——算法锁到整数倍频。

**后果**：心率显示为真实值的整数倍（真实 55 bpm → 110 / 165）或半频（27.5）。

**怎么发现**：
- 相邻窗心率突然跳变（前一窗 55，下一窗 110）
- 频域 vs 时域结果不一致（如频域 53.6 bpm、时域 74.5 bpm，gap ~20 bpm 即同类问题）

**类比**：同一首歌被听成高八度——旋律结构一样，音高翻倍，对不上。

### Q：段参考修正是什么？为什么能救 001？

**段参考修正（segment reference correction）**：利用生理约束——正常心率在相邻窗间不会瞬间翻倍或减半（自主神经调节是平滑的）。

实现：
1. 以段内已确认心率为参考值
2. 当前窗候选心率须与参考一致（合理容差内才接受）
3. 候选为参考的整数倍/半频（典型倍频锁定特征）→ 判定锁错 → 用参考修正，或在正确谐波位置重新找峰
4. 只纠"孤立错误窗"，正确窗不动

**为什么 001 需要它**：管线同时有"多 bin 交叉验证"（同窗多 bin 一致性投票，空间维度纠错）。001 是"好但孤"（心跳 SNR 10.8 最强，但单强反射无冗余 bin）——倍频锁错时空间维度失效。段参考修正用时间维度（相邻窗连续性）兜底，001 探针窗可用率 75% → 100%。

**两条纠错维度**：

| 机制 | 维度 | 适用 |
|------|------|------|
| 多 bin 交叉验证 | 空间（同窗多 bin） | 多反射点冗余 |
| 段参考修正 | 时间（相邻窗连续） | 单反射点（001）、瞬时锁错 |

## 五、多模态对齐

### Q：毫米波、NIR、SART 三个设备怎么对齐？

**不需要跨设备物理连线。** 每个设备各自记录，事后统一对齐。

```
毫米波帧(0..7359) ─── 时间戳 ──┐
NIR 帧(0..N)    ─── 时间戳  ──┼──→ 对齐平台（LSL时钟）
SART markers    ─── 时间戳  ──┘       ↓
                                .xdf 文件
```

各设备的时间戳来源：
- **毫米波**：`_timestamps.csv`（每帧 Unix 毫秒）
- **NIR**：各自帧时间戳
- **SART**：实验事件 marker 时间戳

### Q：怎么知道毫米波的起始帧？

CSV 里第 1 帧的时间戳是 PC 系统收到的实时时间。三个设备都接同一台电脑时，时间戳就是同一个系统时钟，天然对齐。不同电脑则需 LSL 的时间钟校准。

### Q：Python 脚本采集输出的格式是什么？

```
data/sub-{被试编号}/ses-{实验条件}/mmwave/
├── sub-{id}_ses-{session}_mmwave.datacube.bin      PSIC 格式（DebugTool 兼容）
├── sub-{id}_ses-{session}_mmwave_timestamps.csv     帧号,Unix毫秒时间戳（对齐用）
├── sub-{id}_ses-{session}_mmwave_datacube.npz       复数 IQ（8通道 × N帧 × 256bin）
└── sub-{id}_ses-{session}_mmwave.meta.json          采集元信息
```

## 六、模型训练框架

### Q：所有数据都会用来训练模型吗？

**不是。** 各自用途不同：

| 数据 | 在研究中的角色 | 最终产品用吗？ |
|------|--------------|:------------:|
| **毫米波** | 建模对象 —— 模型的输入 | ✅ 核心输入 |
| **NIR（近红外）** | 跨模态验证 + 对比 | ⬜ 可能保留 |
| **RGB 摄像头** | 交叉确认专注状态是否与生理变化同步 | ❌ 隐私/功耗原因 |
| **行为数据**（反应时/正确率） | **标签**——告诉模型"此刻专注与否" | ❌ |
| **被试自我报告** | **标签**——主观专注度评分 | ❌ |

### Q：那训练流程到底是什么？

```
                    ┌──── 行为数据 + 被试报告 → 专注标签
                    │
采集（实验现场）     │        离线处理
────────────────    │        ────────
毫米波 → 原始数据+时间戳 ──→  跑算法 → HR/BR/HRV/微动特征
NIR   → 瞳孔数据+时间戳 ──→  瞳孔特征
RGB   → 头部姿态+时间戳 ──→  交叉验证（不作模型输入）
                    │
                    └──── 对齐 → 特征矩阵 → 训练分类模型
                                              ↓
                                        部署到实时设备
                                        （只用毫米波 ± NIR）
```

### Q：数据要不要实时算出生理指标？

**不要。** 实验现场只保存原始数据 + 时间戳。原因：

1. **算法会迭代**——现在用带通滤波，之后换 VMD。保存原始数据，每次算法升级都能重跑
2. **对齐只能在事后做**——毫米波、NIR、行为数据全部收完才能统一对齐
3. **训练需要批量处理**——收完一批被试后统一跑算法、打标签、训练模型

### Q：什么时候做实时处理？

等模型训练好后，部署到实时设备时才把模型嵌入 pipeline。此时从毫米波输入到专注度输出，延迟控制在几十毫秒。

## 九、数据格式关系

### Q：npz 和 bin 是什么关系？PSIC 格式是什么？

**两者包含相同的数据，但是格式不同，用途不同。**

**PSIC 格式**（Possumic Internal Communication）是正和微芯自己的私有协议格式，就是 bin 文件那 32 字节头的定义。手册里表 4-2：

| 偏移 | 字段 | 说明 |
|:---:|------|------|
| 0-3 | `PSIC` | 文件头标志 |
| 4 | DataType | 0=FFT 数据 |
| 5 | FrameType | 1=1DFFT |
| 6-7 | Rx/Tx 天线数 | 4 / 2 |
| 12-13 | Range FFT Num | 距离 FFT 点数 |
| 20-21 | Max Range | 最大探测距离 |
| 22-23 | Range Resol | 距离分辨率 |
| 30-31 | Frame Period | 帧周期（ms） |
| 32~ | 帧数据 | 裸 payload |

**npz vs bin 的关系：**

```
PSIC .bin                              .npz
─────────────────                     ──────────────────
裸 payload（字节流）                    结构化复数数组
                                       （8通道 × N帧 × 256bin）
每帧不带帧序号（DLL 已剥离）            每帧按天线组好

可回放到 DebugTool 看图                Python 直接 np.load 就能分析
DebugTool 不认识 .npz                 不用关心文件头
```

**同一份数据的不同视角：**
- `.bin` = 给 RadarDebugTool 回放用的
- `.npz` = 给算法同事做分析用的，直接 `np.load()` 拿到复数 IQ

所以 v2 两个都存了，不冲突。算法不用管 .bin，直接读 .npz 就行。

## 文献笔记（2026-08-11）

### Q：mmHRV 这篇论文（毫米波非接触 HRV 检测）的方法是什么？和我们有什么不同？

**来源**：博客转载的 mmHRV 论文解读（cnblogs.com/iot502/articles/16502620.html），基于 TI IWR1843 FMCW 毫米波雷达（2TX-4RX，8 虚拟通道 MIMO），用相位解调提取心跳间隔（IBI）进而计算 HRV。

**系统架构（两个关键部件）**：

1. **目标检测器**：定位人体位置
   - 2D 恒虚警检测（CFAR）：在距离-方位平面自适应估计噪声水平，生成阈值检测人体反射（无需预先校准）
   - 相位信息过滤静态物体（墙壁/家具：无相位变化）
   - 非参数聚类：区分多人（单人多反射点合并）

2. **心跳提取器**：从复合相位信号中提取心跳波
   - 呼吸与心跳运动尺度差异：呼吸 4-12mm / 6-30 次/分钟，心跳 0.2-0.5mm / 50-120 次/分钟
   - 相位信号分解为多个带限分量（EMD 类方法），符合心跳频率范围的分量即心跳波；**同时分解避免逐级分解的错误传播**
   - 峰值检测前归一化：移动平均估计心跳包络 → 原始波/包络比值（抑制幅度漂移）
   - 峰值时间差 → IBI → HRV（RMSSD/SDRR/pNN50）

**与我们管线的方法对照**：

| 环节 | mmHRV | 我们的管线（v1.5） |
|------|-------|-------------------|
| 定位 | 2D CFAR 自适应阈值 + 相位静态过滤 + 聚类 | 距离功率谱峰值 + 距离门控 bin 8-45 + 多候选 bin（定位竞争） |
| 目标判别 | 相位变化（静态物体无相位变化） | 相位调制判别（10s 相位角度变化 <0.01rad 判静态） |
| 心跳分离 | 信号分解（EMD 类）→ 带限分量筛选 | VMD（K=4, heart-only）+ 呼吸谐波 iirnotch 陷波（v9 模块） |
| 心率估计 | 心跳波峰值定位 → IBI | 心跳带主频 + 窄带逐拍检测 → IBI |
| HRV | RMSSD/SDRR/pNN50 | SDNN/RMSSD/LF-HF/SampEn/DFA |
| 质量门 | 未强调（实验场景理想） | SNR≥3dB + IBI 有效率≥0.8 窗级门控（预实验必要） |

**可借鉴的点**：
1. **CFAR 自适应阈值**：我们的定位阈值是固定比例（目标 bin 功率 ≥ 全局最强 30%），CFAR 按局部噪声自适应，可应对距离依赖的噪声差异，值得测试
2. **包络归一化再找峰**：我们窄带逐拍检测直接对带通信号找局部最大；mmHRV 先做移动平均包络归一化再找峰，对抗幅度慢漂移，可降低伪峰
3. **同时分解避免错误传播**：我们 VMD 单次分解即"同时"，此点已覆盖

**局限**：多人检测场景我们不需要（单被试实验）；EMD 类分解计算量大；论文对弱信号/近距杂波（我们预实验的主要痛点）未讨论——所以借鉴 CFAR/包络归一化，不照搬整套流程。

### Q：倪杰等（2024）《基于毫米波雷达的心率变异性检测方法》有什么可借鉴的？

**来源**：倪杰, 王勇, 杨小龙, 等. 基于毫米波雷达的心率变异性检测方法[J]. 移动通信, 2024, 48(12): 103-115（搜狐转载解读）。TI AWR1642（2T4R, 77GHz FMCW），20 名被试 × 10 组 30s = 100 组数据，ECG（Prince 180B）金标准，人体距雷达约 60cm。

**方法（三步）**：

1. **预处理降噪：SSA（奇异谱分析）**
   - 距离-FFT 定位 → 相位提取（扩展 DACM 消相位模糊 + 相位差分：增强心跳、抑制相位漂移）
   - SSA 分解相位信号，窗口大小遍历 1-15s 选 SNR/MSE 最优 → **窗口 10s**；按累积能量 95% 选取特征向量重构
   - 降噪效果对比：**SSA 优于低通滤波（截止 2Hz）和 PCA**（表 1）
2. **心跳提取：VMD + 模态选取准则**
   - VMD 参数：惩罚因子 a=5000，模态数 k=3（与我们 K=4/alpha=1000 不同）
   - 模态选取准则自适应挑出心跳模态（非固定取某阶）
3. **HRV 估计**：心跳波峰值 → IBI → 时频域特征

**实测精度（误差中位数，三方法对比）**：

| 指标 | BPF | mmHRV | 本文（SSA+自适应VMD） |
|------|-----|-------|----------------------|
| 心率绝对误差 | — | — | 均值 1.95 BPM（2.34%） |
| IBI 误差 | 45 ms | 31 ms | **21.5 ms** |
| RMSSD 误差 | 29.06 ms | 19.25 ms | **10.37 ms** |
| SDRR 误差 | 37.53 ms | 11.86 ms | **6.37 ms** |

**与我们管线的对照与可借鉴**：

| 环节 | 本文 | 我们（v1.5） | 可借鉴性 |
|------|------|-------------|---------|
| 相位预处理 | 扩展 DACM + **相位差分**（增强心跳/抑制漂移） | unwrap + detrend（静态对消） | 相位差分替代 detrend 值得 A/B 测试 |
| 降噪 | **SSA 奇异谱分析**（窗 10s, 95% 能量重构） | 带通滤波 + 谐波陷波 | SSA 对低 SNR 相位信号的降噪效果有实测支撑，可测试 |
| 心跳分离 | VMD（a=5000, k=3）+ 模态选取准则 | VMD（K=4, alpha=1000）固定参数 | 模态选取准则（按中心频率/能量自适应挑心跳模态）比固定 K 更鲁棒，中等改动可试 |
| 验证 | ECG 金标准误差中位数 | 频域-时域一致性 + 段参考修正 | 我们缺 ECG 金标准（设备决策见前文 Q） |

### Q：zhr-zhr124/Radar_monitor 仓库（IWR1642 心纹识别+生命体征系统）有哪些可借鉴的信号处理？

**来源**：GitHub 开源仓库（github.com/zhr-zhr124/Radar_monitor，2026-07 更新）。TI IWR1642（2T4R, 77GHz）+ DCA1000，20Hz 实时流 + 离线分析，功能含心率/呼吸率监测、心纹身份识别、四视角融合。信号处理主线在 `signal_processor.py`。

**信号处理流水线（与我们高度同构）**：

```
原始 I/Q → 距离FFT → 多维度联合定位 → 相位差分 → 带通(0.1-5Hz)
→ CEEMDAN+VMD 呼吸/心跳分离 → SVD/CSSA 去噪 → 频率估计
→ 心拍检测（Hampel→DWT重构→R峰→对齐剔除异常）→ HRV
```

**可借鉴的具体方法**：

1. **三维联合定位评分（select_range_cells_multi）**——比我们的"功率阈值+多候选 bin"多两个正交维度：
   - 维度1：归一化方差（时域波动）
   - 维度2：生命体征频带能量比（0.1-5Hz 占全带比）
   - 维度3：**SPC 相邻距离单元相位相干性**——胸腔反射覆盖多个相邻 bin，真实体征单元的相位差分信号与邻居相关性高；噪声单元相位随机、相邻相关低
   - 价值：SPC 与我们预实验定位竞争的痛点（bin3 杂波 vs 人体 bin15-17）正交，可能改善杂波误选，值得 A/B 测试
2. **CEEMDAN → 中心频率分组 → VMD 精细分离**（extract_resp_heart）：
   - CEEMDAN 先粗分，按模态中心频率归呼吸/心跳组（0.05-0.3Hz 为呼吸，其余心跳），再 VMD 精细分离
   - 我们 VMD 固定 K=4 直接分；他们用 CEEMDAN 预分组避免 VMD 模态混叠
3. **CSSA 级联去噪（_cssa_denoise）**：Stage1 四阶 Butterworth 高通 0.5Hz 滤呼吸残余（不依赖奇异向量归属假设）→ Stage2 小窗（L=N//4）Hankel SVD 自适应差分谱截断秩重构。与上一篇倪杰 2024 的 SSA 同族，但级联两阶段更实用
4. **Hampel 滤波（_hampel_filter）**：滑动中位数 MAD 异常检测，**连续异常段整体替换为周围有效值中位数**（避免逐点替换造成阶梯偏移）——对 IBI 异常间隔剔除有直接借鉴（我们目前只用生理范围过滤）
5. **全二维双谱频率估计**：天然抑制高斯噪声与 RSA 调制（RSA 呼吸窦性心律不齐会污染 HRV 频域，双谱对 RSA 免疫）——理论吸引人，实现复杂，标记为"观察项"
6. **心拍级对齐 + 异常拍剔除（extract_beats_from_signal）**：DWT 重构心拍 → R 峰检测 → 对齐 → 剔除异常拍——他们为心纹识别做，对 HRV 的 IBI 序列质量也有价值（我们可借鉴"异常拍剔除"进 IBI 清洗）

**与我们管线的差异**：他们 20Hz 慢时间采样（我们 100Hz），10s 窗口深度分析 + 心拍矩阵；我们 30s/60s 窗 + 窗级质量门。两者质量门思路一致（MAD 离群 + 生理范围 + 能量门控）。

**建议落地顺序**：①SPC 定位评分（预实验定位竞争的针对性测试）→ ②Hampel 连续段替换进 IBI 清洗 → ③CEEMDAN 预分组（如 VMD 模态混叠在弱信号数据上实测有问题再做）。

### Q：Corcoran 2025（Communications Biology）走神的心脏相关标志有哪些方法细节？

**来源**: Corcoran, Le Coz, Hohwy, Andrillon, et al. When your heart isn't in it anymore: Cardiac correlates of task disengagement. Communications Biology, 2025, 8: 1646（共享文件夹 corcoran_2025_heart_cardiac.pdf；2024 bioRxiv 预印本）。N=65，SART + 探针 + EEG/ECG/瞳孔。

**关键方法细节（与我们的分析直接相关）**:

1. **走神 vs 大脑空白的生理解离**:
   - **走神**: 更高的 HRV + 心跳诱发电位（HEP）晚期调制
   - **空白**: 心率、瞳孔、脑-心耦合更显著下降（IBI 与低频 EEG 的互信息）
   - 含义: 我们的探针 4 选项含"走神/大脑空白"——若正式实验标签多样, HRV（走神高）与 HR（空白低）可分离验证
2. **窗长选择**: 状态报告分析用**探针前 10s 窗**（HR/HEP），其他分析用 30s 窗——支持我们 30s 窗合理, 并可补充 10s HR 窗做状态敏感性
3. **心率预测行为**: IBI 更长（心率低）→ 警觉下降、反应更慢更偏; **HRV 高 → 更冲动行为**——与预实验 006 的 rmssd~rt 负相关方向一致（但预实验 Spearman 不显著）
4. **脑-心耦合**: IBI 与 EEG 的 copula 归一化互信息, 带时间滞后（IBI 领先 EEG 50-800ms / EEG 领先 IBI 100-1600ms）——我们无 EEG, 但"呼吸-心率耦合"是毫米波可做的对应物

**对我们的启示**: 生理-行为关联的研究设计（事件锚点+探针+多窗长）与我们的方向一致;
"走神/空白解离"是正式实验有标签后最值得优先验证的假设。

### Q：2025 年 FMCW 雷达 HRV 提取的最新精度水平是多少？

**文献 1**: Cui et al. Non-Contact Heart Rate Variability Monitoring with FMCW Radar via a Novel Signal Processing Algorithm. Sensors, 2025, 25(17): 5607.
- 校准-free 3D 定位（数字波束成形 + 运动目标指示 MTI + DBSCAN 聚类）+ 呼吸/心跳分离的独立相位模型 + **二阶谱稀疏分离（Lagrangian 乘子）**
- 结果: 平均 IBI 误差比 state-of-the-art 降 50%+；限制: 仅限少动场景、离线验证

**文献 2**: Gao et al. Non-contact radar-based HRV monitoring method using adaptive cycle segmentation and peak extraction. J. Meas. Sci. Instrum., 2025, 16(2).
- **自适应周期分割 + 峰值提取**（离散能量信号 + SVM 形态-时域-频谱特征自适应阈值）
- 结果（ECG 金标准）: **IBI 平均误差 8.28 ms（RMSE 15.3 ms）**, SDNN 误差 2.65 ms, RMSSD 误差 4.33 ms, 92% IBI 误差 <20 ms；不同距离鲁棒（远距仅 <6ms 退化）

**对我们的意义**:
1. 方法与我们同构（心跳提取→峰值→IBI），无颠覆性新思路——无需更换管线
2. **Gao 2025 的精度数据是"当前 FMCW 雷达 HRV 的合理基准"**：正式实验若购买 ECG 金标准（设备决策见前文 Q），IBI 误差应期望在 8-20ms 水平；若远超此范围说明管线需要排查
3. "自适应周期分割"（心率随状态时变）与我们的窄带逐拍（主频锚定）思路一致但更精细——作为正式实验前可选优化项（中等改动）

### Q：摄像头（NIR/RGB）与毫米波怎么融合？运动量能预测毫米波质量吗？

**能，而且是预实验唯一跨被试全部显著的多模态发现（2026-08-11 实测）**：

**方法**: NIR 视频 1Hz 运动量序列（帧差能量, 灰度 12.5% 缩放, 5s 平滑）→ 每 30s 质量窗的运动量均值 → 对比 ok 窗 vs 非 ok 窗

**结果（4/4 被试显著, 效应量中到大）**:

| 被试 | ok 窗运动量 | 非 ok 窗 | p | Cohen's d |
|------|-----------|---------|-----|-----------|
| 003 | 5.59 | 8.33 | 0.006 | -0.52 |
| 005 | 3.52 | 7.31 | <0.001 | -1.19 |
| 006 | 8.76 | 12.69 | 0.023 | -0.58 |
| 007 | 1.93 | 5.06 | 0.009 | -0.88 |

**实用方案**: 运动量→非ok 预测 AUC=0.69; 运动量 > P90 的窗直接标伪影（精确率 76%, 误伤 ok 仅 4.5%）; NIR 与 RGB 都有效（d=-0.88 / -0.72）, NIR 略优

**含义**: 摄像头运动量可作为毫米波质量的前置预测器（运动伪影是毫米波窗失败的主因之一）——融合门控方案: 运动量高窗标记为伪影/剔除, 或作为质量评估附加特征。限制: AUC 0.69 说明运动量非唯一因素（定位竞争也贡献失败）。
