# 厚粲杯算法库整理索引

> 更新：2026-08-24。本文用于说明 `08_算法` 的目录边界、主线入口和版本同步规则，不替代各算法脚本的参数说明。

## 主线算法入口

| 分析任务 | 入口文件 | 作用 | 当前使用边界 |
|---|---|---|---|
| 毫米波生命体征基础提取 | `scripts/process_vital_signs_v3_1_1.py`、`scripts/process_vital_signs_v5.py`、`scripts/process_vital_signs_v9.py` | 从距离域复数信号提取心率、呼吸率、心搏峰和质量字段 | 以版本对应记录为准，不按文件名推断最新版本 |
| ECG/RSP 金标准清洗 | `scripts/gold_standard_qa.py` | 清洗 ECG R 峰、IBI 和呼吸带周期 | 作为毫米波校准前置步骤 |
| 毫米波与 ECG 校准 | `scripts/calibrate_ecg_mmwave.py`、`scripts/validate_gold_anchor.py` | 做时间对齐、心率/IBI 对照和质量门控验证 | 低质量或半频/倍频窗口不得进入正式生理统计 |
| 呼吸带门控 | `scripts/run_rsp_gate.py`、`scripts/export_rsp_rates.py` | 提取呼吸率并生成呼吸质量标记 | 用于识别呼吸谐波污染，不把门控结果当作自动纠错 |
| 正式实验时间门控 | `scripts/behavior_time_gate.py`、`scripts/run_timeline_gated_mmwave_quality.py` | 只保留正式基线和 Block 内数据 | 排除练习、休息、说明和收尾 |
| 正式行为和事件分析 | `scripts/analyze_formal_behavior.py`、`scripts/analyze_formal_probe_centric.py`、`scripts/analyze_formal_event_related.py`、`scripts/analyze_formal_vigilance.py` | 连接行为、探针和毫米波质量结果 | 先完成单模态结果，再进入融合 |
| 多模态与被试外验证 | `scripts/evaluate_j_multimodal_loso.py`、`scripts/build_evaluate_j_mmwave_m1_loso.py` | 进行留一被试验证和增量审计 | 禁止随机拆分同一被试的相邻探针 |

## 目录边界

- `scripts/`：当前可运行脚本；`scripts/archive_历史版本/` 只用于追溯，不作为主线入口。
- `docs/`：方法、报告、清洗标准、交付包、运行手册和项目管理说明。
- `data/`：小型、可版本化的审计数据和派生质量表；不放原始波形、视频或隐私数据。
- `output/`：可重新生成的本地结果、图片和批处理产物；通过报告或资源索引定位，不默认推送。
- `01_Attention-Analysis_nvidia-cuda/`、`external/attention-pipeline-v2/`：NIR 独立工程，保留其内部 Git 历史；主库记录其来源和版本，不把虚拟环境混入主库。
- `11_数据/`：原始数据保持原位置不动；已确认属于算法派生的小型质量表已迁入 `data/质量/`。

## 模型权重

模型权重包括 DeepVOG、YOLO、RITnet 和相关 ONNX/PT/H5 文件。它们通过 Git LFS 管理，规则见根目录 `.gitattributes`。训练过程 `runs/`、虚拟环境和缓存不进入主库；正式推理所需的 canonical 权重应保留在 NIR 工程的 `runtime/*/models/` 或模型目录中。

## 当前已知风险

1. 两个 NIR 工程均存在本地独立 Git 历史，且至少有未提交改动，不能通过主库提交自动覆盖。
2. 部分正式质量汇总表来自旧版本路径，尤其是距离单元异常的记录，需要以最新验证脚本和输出重新核对。
3. `output/` 中有大量历史和当前结果，不能只按文件名判断版本；正式报告应同时记录脚本版本、输入数据范围和质量口径。
4. 任何移动脚本后都必须运行路径引用检查和 Python 编译检查，避免交付包中的相对路径失效。
