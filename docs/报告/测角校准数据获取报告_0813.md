# 测角校准数据获取报告（2026-08-13）

## 背景

官方手册附录 6.1 确认 RS624X 测角必须做：①速度补偿（mmw_get_dec_fcw）②软件天线校准（mmw_ant_calib_data_get，RS624X 不能用硬件校准）。但 DLL 不暴露命令响应 payload，需要自建通路从固件读取这两项出厂数据。

## 通路方案（最终版，已实测成功）

```
PC SendData(0x41, sub_id=28)  → 固件 ant_calib_handler
  → mmw_get_dec_fcw() + mmw_ant_calib_data_get() 读取出厂数据
  → 填充 g_calib_payload[36] (dec_fcw 4B LE + ant_calib_data[8] 32B LE)
  → 置 g_calib_report_status = 0xBB1C (触发标记)
  → datacube 上报路径状态机检测 0xBB1C:
      0xD001 (传输开始) → 18 数据帧 (每帧 rsv1/rsv2 携带 2 字节)
      → 0xD002 (传输完成)
  → PC 从帧头 rsv1/rsv2 (payload[6:8]) 重组 36 字节
```

- 传输时长: 20 帧 ≈ 0.2 s
- 协议定义: `0x55AA`=空闲 `0xBB1C`=命令收到(触发) `0xD001`=开始 `0xD002`=完成，其余=数据帧

## 实测结果

- **dec_fcw = 464703** (U32Q20，速度补偿系数)
- **ant_calib_data[8]** (S16Q15 复数，模组特有出厂值，与源码默认数组不同):
  - [0] 19609+0j, [1] 20244-25028j, [2] -32547+18787j, [3] 21824-16773j
  - [4] 20282-50j, [5] 20853-26042j, [6] -32767+19518j, [7] 22680-17843j
- 数据已固化: `11_数据/calib_data/ant_calib.json`

## 关键技术决策与经验

1. **0xC6/0xC7 消息通路判死**: DLL V1.1 反编译确认 `DrawingDataProcess.HifRepSeqDataProcess` 仅有 0xC1/0xC2/0xC3 分支，0xC6/0xC7 消息到达即被静默丢弃（DLL 文档声称支持 dataType=0/1，实现缺失）。三个 DLL 副本 MD5 一致，无更新版本。
2. **g_calib_payload_valid 传递不可靠**: handler 写 1、状态机读 0（反汇编地址一致 gp+1972，运行时行为不一致，根因未明）→ 废弃，改 `g_calib_report_status == 0xBB1C` 直接触发。
3. **static 变量 .bss 残留**: `calib_stream_idx` 做 static 时软复位/烧录后残留旧值（19），导致传输跳过 D001 直接 D002 → 改全局变量 + handler 显式重置。
4. **DLL SendData 假成功排除**: errorCode 交替实验（0x50→1, 0x41→0）证明 ACK 真实，命令确实送达。
5. **命令发送时序**: 需按 demo 完整流程 StopCollectingData → WakeupDevice → StopRadar → SendData → StartRadar。

## 测角验证（sub-1d-test 数据）

- 目标 bin 18 (0.67m)，与 0.7m 目标吻合
- **天线校准生效**: 固定失配被修正（通道2 相位差 mean -0.803→-0.020 rad）
- **逐帧测角不可行**: 校准后通道间相位差 std 仍 1.0-1.2 rad（chirp 相位不连续，硬件限制，与 8/12 结论一致）
- **时间平均测角存疑**: 长窗收敛 +8.4°（std<3°）但逐帧均值 -1.1°，两者矛盾，无已知角度金标准无法判定

## 结论

校准数据获取链路已打通（0x41 → rsv 帧头传输 → PC 解析），但 RS6240 1D/ADC 数据测角仍受硬件 chirp 相位不连续限制。测角续路：2D 固件数据（带多普勒维度可做速度补偿）或已知角度摆位验证。
