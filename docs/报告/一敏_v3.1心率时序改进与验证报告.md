# v3.1 心率时序改进与验证报告_0813

## 适用数据范围

本轮只使用以下三组可用数据：

- `sub-deep-breath`
- `sub-rest_3min`
- `sxq`

`sub007`、`sub008` 和其他数据不参与算法选择或结果验收。

## 改进目标

旧图中的 `HR time-course` 直接使用相邻心跳峰间隔计算瞬时心率：

```text
HR = 60 / IBI
```

伪峰、漏峰和谐波锁定会被放大成大幅跳变。v3.1 改为在固定 25 秒窗、5 秒步长上计算并融合：

1. 稳健局部 IBI 心率；
2. 局部心跳频谱心率；
3. 严格 2:1 倍频/半频修正；
4. 基于时频一致性和峰间期规则性的置信度；
5. 置信度加权的双向连续轨迹。

原始逐拍心率没有删除，仍以淡色散点保留在结果图中。每个窗口同时输出 `time_bpm`、`freq_bpm`、`fused_raw_bpm`、`fused_bpm`、`confidence`、`time_freq_gap_bpm` 和 `quality`，避免把平滑曲线误认为原始测量。

## 结果解释

- `rest_3min` 最稳定，所有窗口均为高质量，时域和频域高度一致。
- `sxq` 的长记录存在若干真实的缓慢升降，同时旧峰序列有成段 2 倍锁定。v3.1 折回严格谐波，保留非谐波变化；但高质量窗口仍只有约一半，后续使用时必须做窗口筛选。
- `deep-breath` 开头存在时域和频域共同支持的约 90 BPM 到约 60 BPM 过渡，不能仅因全局心率约 60 BPM 就强行折回。v3.1 保留该变化。
- `sxq` 和 `deep-breath` 仍有较多非高质量窗口。后续专注度或 HRV 分析应使用 `hr_course_quality_code >= 1` 或 JSON 中 `quality != "low"` 的窗口，不应把所有点等权使用。
- 当前改进解决的是 HR 时序展示和局部时频融合。HRV 仍不应直接使用旧的全量原始峰间期结果；需要另行建立带伪峰/漏峰质量门控的 NN 间期序列。

## 行为对齐与完整心跳波形

- `sub-deep-breath` 每次运行都会读取同一采集目录中的 `markers.csv` 和雷达 `timestamps.csv`，按绝对时间将 `seg1` 到 `seg5` 映射到心跳波形与 HR 时间轨迹。因原始标记没有说明各段具体行为含义，结果保留原始 `seg` 名称，不擅自改成呼吸/静息标签。
- deep-breath 主结果图的心跳面板使用完整记录，不再只显示最后 20 秒。另存 `deep_breath_v31_raw_heart_behavior_aligned.png`，包含全程心跳波形、全程 HR 时间轨迹和五个完整分段。
- `sub-rest_3min` 没有事件级 beh 文件，结果按会话级 `REST` 标记；`sxq` 没有与该次雷达采集时间相匹配的事件级 beh 文件，结果明确标记为 `session_only_missing_event_beh`。不能拿 `sub007/sub008` 的异时 beh 数据强行配对。
- 修复了采集分块读取顺序：首个 `*_datacube.npz` 是第一批 1000 帧，随后才是 `*_datacube_part001...`。旧流程只匹配 `part*`，会漏掉开头约 10 秒；修复后 `sxq` 为 280,288 帧、`sub-rest_3min` 为 17,786 帧、`sub-deep-breath` 为 50,487 帧，均与各自时间戳文件完全一致。
